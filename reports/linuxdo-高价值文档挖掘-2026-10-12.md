### B · Agent 架构与编排

**#5 `1870593` 御舆：解码 Agent Harness（42 万字）**
在 Claude Code 51 万行 TS 泄露事件当晚通宵 vibe 出来的**整本书**，15 章，从对话循环到"构建你自己的 Agent Harness"。作者自述动机极有价值：**"群里每一条都很有东西，但它们是碎片"**——权限系统的截图在这个群、上下文压缩在那个群、流程图在第三个群，**没人把这些拼在一起**。
- 开源：`lintsinghua/claude-code-book`（另附在线读书站）。

**#6 `2053844` Claude Code 上下文管理笔记（1.7 万字）**
作者明确拒斥"一眼 AI 生成、追热点"的源码分析，**自己动手读、要求 AI 给出每部分源码位置**再自己理解总结。内容含：一轮对话的上下文结构（System Prompt + Tools + Messages）、`MAX_OUTPUT_TOKENS_FOR_SUMMARY = 20_000` 的压缩预留、**Canonical Transcript**（`~/.claude/projects/{project}/{session}.jsonl`，会话恢复的唯一真信息源）。
- 评论区延伸出好类比：**"multi-agent ≈ 进程/线程，上下文管理 ≈ 缓存管理（LRU）"**。

**#7 `2894461` 3 亿 token 换来的 codex 子代理编排方案**
**可直接抄的工程件**：全局 `AGENTS.md` 里的"## 子代理"规则（谁来派、派几个、`fork_turns="none"`、默认只读、机械修改要有文件所有权与验收方法、主代理不重读全部文件…）+ **6 个 agent 的 TOML 全文**（`default` / `quick_scan` / `code_explorer` / `mechanical_editor` / `reviewer` / `verifier`，各自绑定模型与 reasoning effort）。
- 附带结论：`gpt6` 时代**强烈推荐用 `create_thread` 开新对话并行**，效率提升"异常明显"；中转站没有 luna 就换 terra low，甚至路由到 DeepSeek/Grok。

**#8 `1541126` Clawdbot/OpenClaw 爆火底层原理**
论证"**本地桌面 Agent 是被压抑的巨大需求**"，并点破行业不敢做的两个死结：①安全/隐私/责任（主力机理硬盘 = 官司与公关灾难）；②适配性（4K/1366 分辨率、暗色模式…）。
- Moltbot 的解法是换赛道：**"专用机桌面 Agent"** + 开源社区共创 = **权力与责任对等**（不收费就不背格式化你硬盘的锅）。
- 评论区补充行业脉络：`Warelay → Clawdbot → MoltBot → OpenClaw`，一天涨 13k 星；Vibe Coding 发明人提出 **LLM > LLM Agent > Claws**。

**#9–#12 学习路径与索引**
- `1865600` Agno 框架逐行讲（含 `db`/`tools`/`num_history_runs` 的配置注释），**小白友好**；
- `1868608` / `1773955` 是"从零构建 Code Agent"两本开源材料（后者是 `learn-claude-code`，**每次只加一个机制**的渐进教学）；
- `2504439` 是 Pi 生态的**索引文档**（教程/插件/使用习惯/第三方扩展四段），评论区有反方"pi 主打极简，没必要整理，且 1.0 会破坏所有扩展"。

**#13 `2993279` vibe coding 教程**
五条可操作原则：**先让 AI 在 GitHub 深度搜索有没有现成轮子**（按 star + 近期维护判断）；**开工前充分讨论对齐颗粒度**（万能句："如果你还有任何问题或建议可以先向我提出，解决所有分歧和阻塞后再执行任务"，建议放结尾或全局指令）；方案用最强模型、执行可换性价比模型。

**#14 `3005257` AGENTS.md 工程化（8785 字）+ 反方**
楼主的目标是纠正 GPT6 的两个毛病：**少问多做**、**别总写脚本把活干了**（"防止在仓库里产出一堆垃圾脚本，方便人接手"）。
- **评论区才是精华（反方论点）**：维护者从 200–300 行砍到 **40–50 行**，发现"模型能力提高后，过于复杂的规则反倒限制了效果"；引用 OpenAI《Rethinking skills and prompts for GPT-6 Astra》；结论倾向 **AGENTS.md 应该越来越薄**，个性化约束更适合放 hook 或记忆偏好。

### C · 提示词工程

**#15 `856257` 个人的 AI 提示词构建分享（7.4k 字）**
把提示词拆成 **system（出厂设置/灵魂）** 与 **user（后续发言）**，强调"别以为写了系统提示词后面说什么就不重要了"。两条核心操作：**词汇要与你的习惯一致**（你用"函数"就别在提示词里写 function/feature，否则增加模型"认知负荷"）；**用第一人称"我是XXX"定义角色**（"你是一个工程师"战斗力 1 vs "我是工程师"战斗力 5）。
- **评论区纠偏很有价值**：这套解释"过于拟人化"，真实机制是**词汇模式匹配高质量语料**（提"鲁迅"就提高鲁迅相关词的输出概率），并非"心理暗示"。

**#16 `1900133` 万字提示词工程方法论（PDF 附件）+ 讨论区**
正文只有 59 字（发的是 1.2MB PDF），但**回帖是一场高质量辩论**：
- 主流反方：**"早进入 context engineering 和 harness engineering 时代了，提示词写得越多，限制越多，智能越差"**；
- 正方：**"context engineering 也得落到具体 prompt，只是从写一大段进化成决定给模型看什么、不看什么；客服/内容/教育等单轮场景 90% 还靠 prompt"**；
- 实操技巧：**把最重要的指令移到提示词末尾或用 XML 单独包裹**（长上下文里模型对首尾注意力最高，中间易丢），并写"这条规则必须严格遵守"。

**#17 `613788` 提示词指西 + 破限笔记（1.37 万字）**
前半是扎实的**提示词编写基础**：先明确"要求与目的"→ 不写模糊要求 → **尽可能给示例** → 写完自检有没有内在矛盾。用"猫娘"举例演示"模糊要求如何逐步补全成可执行规格"。
- ⚠️ **红线**：后半是破限/越狱（CoT 套取、绕外部审核），**不适合进客户培训材料**；只取"基础编写"与"CoT 要有输出才有作用"这类中性结论。

**#18 `1923706` 如何写一个好的 skill（3.5 万字 / 155 回复 / 15,034 浏览）**

### D · 知识库 / RAG / 记忆

**#20 `1907342` Karpathy 式"会自己生长的知识库"**
落地版做法：建三个文件夹（`raw/` 原始素材、`wiki/` AI 整理的产物、`outputs/` 回答与报告）+ 写一个 **schema 文件（CLAUDE.md/AGENTS.md）** 告诉 AI 规则（每个主题一个 md、开头写摘要、`[[主题]]` 互链、维护 `INDEX.md`、新素材入库要同步旧条目）。
- **"你只做两件事：采集和提问。AI 是图书管理员。"** 存得越多，知识库越聪明。
- 评论区补链：Karpathy 后来单独整理成 `llm-wiki.md`；有读者指出这可以**在 RAG 前面加一步"入库即优化旧知识"**。

**#21 `2720669` RAG 全链路拆解（1.12 万字）**
从 chunking、embedding、存储到输出给 LLM 当证据，全链路覆盖，并**单开一章反驳"RAG 已死"**。核心论点：**RAG 不是某套固定流程，而是"检索—增强—生成"的工程范式**；skills 的渐进式披露、Agent Memory 都可算 RAG；真正被淘汰的是早期粗糙实现，不是思想本身。

### E · 安全 / 风险

**#24 `2416059` 黑 GEO：给大模型搜索下毒（2.6k 字）**
作者**亲手实验**：编造一个不存在的"OSINT 专家张伟"，在主流大模型里把它搜成了该领域第一位，并找 4–5 人交叉验证结果一致。投毒四步：**确定被投毒内容 → 分析模型引用源 → 反推搜索关键词 → 若答案未采信则分析采信源并迭代**。引用源优先级：政府/机构/媒体/**与模型同归属的社区**（可控性最高）。
- 防御讨论（评论区）：TLD 信誉（gov > 廉价 TLD）、Whios、AS、SSL、**多语言结果交叉**（只有多语言都有的才采纳）、权威库反查（提了人就查 GitHub/arXiv）；本质是**成本博弈——把投毒成本抬到不划算**。
- 可用点：这是给"AI 输出可信吗"这个话题准备的**最有力弹药**，比讲道理强。

**#26 `563272` AI 浏览器自动化实战** —— Browser use 三件套（`browser-use` CLI / `web-ui` / `macOS-use`）本地搭建全流程，含源码原理穿插。评论区小坑：**DeepSeek 不支持视觉，用 web-ui 要取消勾选**；另有"Browser use 更专注浏览器自动化，MCP 更重生态整合"的对比。
