## 0. 一句话结论

两份材料的**价值方向完全相反**，但都对培训有用：

| | 材料 A（编排指南） | 材料 B（人设技能清单） |
|---|---|---|
| 是什么 | Codex / Claude Code 的**重编排方法论** | 55 个"把一个人蒸馏成 skill"的**生态索引** |
| 能不能直接发学员 | ❌ **不能**（语境不匹配） | ⚠️ **部分能**（需分层筛选） |
| 该放哪 | **讲师备课 + 少数进阶者的延伸阅读** | **材料包的 L2 / L3 / L6 三处直接注入** |
| 最大的增量 | 给讲师一套"编排"的知识底座 | 一个**现成的 skill 质量量规** + 一个**必须正面回应的员工焦虑** |

其中最有价值的一条：材料 B 里有个 **★2,439 的「反蒸馏.skill」**——教员工把核心知识抽掉、留个看起来完整的壳交差。**这正是本次培训最大的隐患，而现有讲稿完全没有回应它。**

## 1. 材料 A：Agent 编排实操指南 —— 结论是「别当教材发」

**现状体检**：正文 5,879 字｜11 张表｜2 张画板｜4 个高亮块｜2 段代码块。章节：三个数字三条红线 / 术语对齐 / 选型（四范式矩阵 + 场景速查）/ 实操三连（模型分工 · AGENTS.md · 多会话）/ 踩坑清单 / 反方观点 / 工具选型。

**问题是语境**：全篇讲的是 `AGENTS.md`、`subagent`、`git worktree`、`Astra / Sol / Luna` 分工——那是 **Codex / Claude Code 的语境**。而客户手上的工具是**豆包工作客户端**。

> 如果直接发下去，学员会以为"要在豆包上写 AGENTS.md、配 subagent"，然后发现根本找不到入口——**这比不发更糟**。

**建议的用法（三选一或叠加）**：

| 用法 | 说明 |
|---|---|
| **① 讲师备课** | 讲师要能回答"以后要不要上更重的编排"，这份是底座 |
| **② 抽一页"厂商中立的编排常识"** | 只留「三个数字三条红线」「四范式对比」「踩坑清单」三节，去掉所有 Codex 专有名词，作为 L3 进阶阅读 |
| **③ 少数进阶者的延伸阅读** | 明确标注「面向编码 Agent 语境，与豆包工作客户端不同」，只在学员主动问"更专业的做法"时给 |

**绝对不能做的**：把它当作现场演示或岗位练习的教材（第 10–25′ 和 25–45′ 都不适合）。

## 2. 材料 B：awesome-persona-skills —— 生态测绘

### 2.1 体量：这是个真生态，不是玩具

仓库本体只是**一份策展清单**（只有 README.md 11.6 KB + README_EN.md 12.7 KB），但它是入口。清单收录 **55 个 skill，8 大类**，头部项目的量级：

| 项目 | ★ | fork | 一句话 |
|---|---|---|---|
| **女娲.skill** `alchaincyf/nuwa-skill` | **34,115** | 4,528 | 蒸馏任何人的思维方式（心智模型 / 决策启发式 / 表达 DNA） |
| **同事.skill → Distilly** `titanwings/colleague-skill` | **25,508** | 2,189 | 把同事的思考方式蒸馏成可复用 Skill |
| **中国专利.skill** `handsomestWei/patent-disclosure-skill` | **11,332** | 1,201 | 专利点挖掘、交底书、申请文件、检索、审查答复（**今天还在更新**） |
| **反蒸馏.skill** `leilei926524-tech/anti-distill` | **2,439** | 287 | 清洗被迫写的 Skill，留壳交差 |
| 图鉴.skill `Aar0nPB/curator-skill` | 5 | 3 | 跨作者 persona 路由调度器 |
| 汇报.skill `Luious-LYH/huibao-skill` | 4 | 0 | 把零散材料写成日报/周报/阶段汇报 |

> 对照：**女娲 3.4 万星 > linux.do 站内任何单个 AI 帖的热度**。这是个现象级生态。

### 2.2 四层分级：哪些能用、哪些只能当例子、哪些必须拒绝

#### ① 可直接进培训

| Skill | 为什么对口 |
|---|---|
| **中国专利.skill** | 半导体公司专利申报是**刚需**。它把 9 项能力做成**子技能路由**（交底 / 申请 / 检索 / 解读 / 对照表 / 地图 / 审查答复 / 政策简报 / 案卷），每项都在 `skills/*/SKILL.md` 里，根文件"只做路由"。**这就是"文件夹化 skill"的工业级样板** |
| **汇报.skill** | 与讲稿的「研发周报汇总技能」**直接同构**，可做对照范例。它的原则极干净：**"当前材料决定说什么；汇报人格只决定怎么说"**，且明确"不编造数字、成果、人物、时间" |
| **仓颉.skill** | 把书 / 长视频 / 播客里的方法论蒸馏成可调用的 skill → 对应讲稿的"知识沉淀" |
| 写作.skill / PPT.skill | 文档与汇报材料，L5 模板库的旁证 |

#### ② 教学示范：讲"好 skill 长什么样"

**女娲.skill 是这次最大的方法论收获。** 它有一套完整的**工程化蒸馏流程**：

- **六路并行调研**：`01-writings` / `02-conversations` / `03-expression-dna` / `04-external-views` / `05-decisions` / `06-timeline`——每路一个子 agent，**"不存文件的调研等于没做"**
- **自包含原则**：所有调研文件必须存在 skill 目录内部，"复制整个目录就能独立使用"——**这就是"简单任务单文件、复杂资料按需读取"的可执行版**
- **蒸馏档位**：快速（3 维）/ 标准（6 维）/ 深度（6 维 + 一手素材全量），且**开跑前必须说清成本**（"顶级模型单次可消耗数十美元"）
- **质量验证**：`Phase 4 验证 → Phase 5 双 Agent 精炼`，**迭代上限 2 次**，2 轮不通过就"在诚实边界标注薄弱维度，交付当前最优版本而非无限打磨"
- **保真度评分卡**（100 分制）：立场一致性 30 / 风格辨识度 20 / 边缘诚实度 20 / 来源透明度 15 / 结构完整度 15。实例（Karpathy）拿到 **97/100**，评语写明"扣分在个别段落英文短语密度略高"
- **评测分离依据**：引 SkillLens 论文——**LLM 自评准确率仅 46.4%**，故"答题与评分严格分离"
- **信息源黑名单**：知乎 / 微信公众号 / 百度百科 永远排除（洗稿、无法验证、二手转述）

> ⭐ **把「保真度评分卡」改造一下，就是现成的 skill 验收量规**。讲稿现在只有定性的"四个共同点"，缺一个能打分的表——这是本次可直接补上的最硬的一块。

**图鉴.skill** 则是"**路由**"的活标本：它的 `description` 里写了**触发词、被动触发、以及"必须保持沉默"的不触发条件**，还有明确的 redirect 规则（想创作新 persona → 转给女娲）。它甚至论证了为什么需要它：**"Claude 自己模仿 X = 纸糊的 X；真 skill = 完整的认知 OS"**。

这与讲稿「Description 怎么写：让正确的任务找到正确的技能」**是同一件事的工业实现**。

#### ③ 必须正面回应的现象：反蒸馏

**`anti-distill` ★2,439** 的存在，是一记警钟。它的工作方式是：

- 三档清洗强度（轻度 80% / 中度 60% / 重度 40% 保留度）
- 对每段打标签：`[SAFE]` 通用知识（去掉反而露馅）/ `[DILUTE]` 可泛化 / `[REMOVE]` 核心不可替代知识 / `[MASK]` 敏感信息
- **输出两份**：一份"看起来完整且专业、但核心知识已被抽掉"的**交差文件**，一份留给自己的**私人保留清单**——原文写着"**带着这份清单跳槽，它比任何 Skill 文件都值钱**"
- 验证要求：字数比 85–115%、所有二级标题必须存在、要点密度差异 < 30%、术语不降级——**"看起来像真的"是它的硬指标**

**这意味着什么**：你让工程师写 skill，他们的第一反应可能是"这是要把我替代掉，那我留一手"。**2000+ 星说明这不是个别人的想法。**

→ 现有讲稿（0–10′ 的价值章、25–45′ 的技能章、53–60′ 的答疑）**没有任何一处正面回应这个焦虑**。这是必须补的。

#### ④ 明确排除

`前任.skill` / `初恋.skill` / `暗恋对象.skill` / `现任.skill` / `她.skill` / `永生.skill` / `重逢.skill` / `父母.skill` / `兄弟.skill` / `相亲.skill`（人际关系 + 情感陪伴两大类，共 11 个）

**不进企业培训**，三条理由：
1. **合规**：蒸馏"前任""父母"涉及**未同意的他人数据**
2. **情绪负载**：现场涉及私人情感，风险不可控
3. **无关**：与半导体业务零关联

网络名人 / 传统文化哲学两类（郭德纲、特朗普、赛博算命、金刚经…）——**只作为"生态有多大"的举例，不作教材**。

## 3. 三个来源交叉印证：指向同一套判断

材料 A、B 与上一轮的 linux.do 挖掘，在四个点上**互相印证**：

| 判断 | linux.do 站内（1923706 等） | 讲稿（你的） | 材料 B（GitHub） |
|---|---|---|---|
| **Description 决定被不被选中** | "描述写清触发场景" | "让正确的任务找到正确的技能" | 图鉴的触发/不触发/重定向规则 |
| **单文件 vs 文件夹化** | "1.1 单文件；1.2 文件夹化" | "简单任务从小结构开始，复杂资料按需读取" | 中国专利"根文件只做路由，六段封面在子包" |
| **评测必须分离** | "同时测试调用是否正确、结果是否准确"；"子代理只该读不该写" | "同时测试调用与结果" | 女娲"答题与评分严格分离"（自评准确率仅 46.4%） |
| **skill 质量要能量化** | （未涉及） | 只有定性"四个共同点" | ⭐ **保真度评分卡（100 分制 5 维）** |

**结论：材料 B 补上了前两者都缺的那块——量化验收。** 而材料 A 补的是"编排"这一层的知识，属于讲师的底座而非学员的教材。

## 4. 对培训的具体增量（可执行）

### 4.1 材料包（学员自学包）改动清单

| 层 | 改动 | 依据 |
|---|---|---|
| **L2 岗位练习卡** | **新增第 6 张：知识产权 / 专利交底**（岗位：研发、知识产权） | 半导体的真刚需；中国专利.skill 11.3k 星验证了需求 |
| **L3 写 Skill 深入** | 增加「**工业级 skill 长什么样**」两范例：① 中国专利（多子包路由）② 汇报（证据底稿 + 受众渲染） | 比现有抽象原则更易模仿 |
| **L5 模板库** | **新增「Skill 体检 5 问」**（由女娲保真度评分卡改造：立场一致 / 风格辨识 / 边界诚实 / 来源透明 / 结构完整） | 补上讲稿只有定性标准的缺口 |
| **L6 常见问题** | **第 1 条改为："公司让我写 skill，是不是要替代我？"** 正面回应，并说明"什么叫留在壳里的假知识" | 反蒸馏 ★2,439 的存在 |
| **L1 概念速查** | 加一页「skill 生态有多大」——举 3 个数字（女娲 3.4 万星 / 同事 2.5 万星 / 专利 1.1 万星）说明"万物皆可 skill"，同时点明**"能装 ≠ 有价值"** | 生态测绘结论 |

### 4.2 讲稿建议补两处（你的文档，未改动，仅建议）

1. **动机回应**：在 25–45′ 开始写技能之前，用一句话正面回答"这是不是要替代我"——不然学员会自己找答案（而网上的答案叫反蒸馏）。
2. **"适合做成技能的任务"补一类**：现在列的是「周报 / 费用检查 / 流片对比」，建议补**高频文书型**（专利交底、技术汇报）——更贴半导体、且是研发的日常痛点。

### 4.3 安全红线（必须写进材料包）

学员看到这份 GitHub 清单后，**一定会有人去装第三方 skill**。站内 `1374400` 已给出结论：**装第三方 skill = 把用户权限完整交出去**（可读 `~/.ssh`、`.env`）。

→ 材料包必须写：**"从 GitHub 装任何 skill 前，先走内部准入"**，并把"看清单可以、照单安装不行"讲明。
