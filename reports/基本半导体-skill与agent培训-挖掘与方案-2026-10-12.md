## 〇、先给结论（TL;DR）

**一句话定调**：客户是硬科技制造 IDM，听众是微电子／电力电子／材料背景的工程师（**不是软件工程师**）。这决定了培训的重心**不是"教操作"**，而是三件事：

1. **场景落地**——把他的日常活（测试报告、失效分析、datasheet、客户问答）接上 AI
2. **成本与合规可控**——半导体企业内网隔绝、数据不出厂，渠道和成本是真实痛点
3. **先立边界**——"AI 辅助"与"AI 全权接管"的红线必须在课堂上钉死

**站内挖掘的三个硬结论**：

| 结论 | 依据 |
|---|---|
| 站内**没有**半导体行业的现成 AI 落地案例（全是模型评测和行业新闻） | 关键词横跨标题/正文/回复三层扫描，半导体相关帖 76 条，无一是"行业内如何落地" |
| 但**通用教学方法论**极其丰厚，足以撑起一整套课件 | `1923706` 一篇 3.5 万字 skill 方法论；`803265` 站内圣经 605 回复 |
| **同行（医疗行业）已经在花钱买同款服务** | `1888765`「有偿找人给团队做 Claude Code 培训」——需求方非技术背景，要"科普扫盲+一点实操" |

## 二、他们真正要什么：需求真相

站内 `1888765` 是一份**同类需求的活标本**（医疗行业，付费找人做培训）。把 34 条回复读透，能直接读出客户的心理：

→ 培训的**认知门槛必须压到地板**，前 1/3 时间要花在"这是啥、能干啥、不能干啥"。

**② 培训的价值锚点不在"操作"，在后端。**
> William.Chase：「其实远程指导，然后再加上积极回复就好了。**更重要的其实是订阅、成本管控、中转建站。其次才是使用**，使用算是小事情了。」

→ 这句是**课程配比的直接依据**：企业客户真正付费买的是"渠道怎么搭、成本怎么控、用起来不出事"，不是"点哪个按钮"。

**③ 有明确的反方声音，课堂上必须正面回应。**
> skylerzhang：「**这玩意培训没用，得自己折腾**」

→ 不能装作没听见。对策：把培训做成**工作坊**（带真实任务当场跑通），而不是讲座——用"当场出活"回应"培训没用"。

**④ 半导体行业多一条刚需：内网隔绝。**
站内 `2962465` 是同类企业场景的直证：
> 「我们公司需要**隔绝互联网开发**，现在公司部署了一套**开源的千问大模型**，日常基本够用……领导想要用这个大模型，搞一套给个设计图就能还原前端页面的工作流」

→ 基本半导体作为 IDM，**内网/私有化部署几乎是默认前提**，这一点必须进培训（见第七章）。

## 四、能力支柱：Skill 怎么写（培训核心内容）

`1923706` 作者把这套方法论压成**三句话纲领**，可作整个 skill 模块的骨架：

> **① 结构服务于内容　② 激活优于存储　③ 结构可复用，内容禁止预制**

拆成可教的要点：

### 4.1 先厘清三个词的分工（避免听众混淆）

| 概念 | 管什么 | 类比 |
|---|---|---|
| **RAG** | 外挂知识库，让 Agent **有据可依** | 查资料 |
| **MCP** | 让 Agent **能探索外部世界** | 长出手脚 |
| **Skill** | Agent 流程的**大脑**，决定"该怎么做" | 定规矩 |

> 原话：三者"根本目的都是优化执行流程，只是各管一段"。

### 4.2 Skill 的本质：打包的"能力"

Skill = 提示词 + 规则（md）+ 脚本（sh/py）+ 文档，打包成一个能力。

**相比 Prompt 的本质优势——渐进式披露（按需加载）**：
> "agent 不会每一次都把 skill 的全部内容塞进上下文，而是先读 description，命中后才按需读" —— **这既精简上下文，也省钱（原文：这才是最重要的！！）**

→ 对企业客户，"**省钱**"是比"先进"更有效的说服话术。

### 4.3 可直接抄的教学范式：「原则 + 检验句」

不要写"保持简洁"（声明），要写成：
```markdown
## 简洁优先
解决问题所需的最少代码，不写投机性的功能。
检验：资深工程师会觉得这过度复杂吗？如果是，就简化。
```
> 原理：声明只能让 Agent"记住"，检验句给了它**执行后可自我验证的钩子**。

### 4.4 结构何时该从"单文件"裂成"文件夹"

**先答三个问题**，全"否"→单文件就够：

| 问题 | 否 | 是 |
|---|---|---|
| 有多少个不同主题？ | < 3 个 | 分裂 |
| 绑定多少种任务流程？ | 没有 | 需要 workflows/ |
| 会长久演进吗？ | 不会 | 需要自演化机制 |

**文件夹化后的结构**：
```
skills/<name>/
├── SKILL.md      # 入口：路由表 + 优先级
├── rules/        # 长期约束（指令性的"你必须做 X"）
├── workflows/    # 步骤流程（"我现在该做什么"）
├── references/   # 背景资料（警告性的"小心 X" → gotchas.md）
└── scripts/      # 辅助脚本
```
> 分类窍门（作者原话）：迷茫时挠挠后脑勺问自己——"我能做 X 吗？"→ rules；"这个坑怎么避？"→ references；"我现在该做什么？"→ workflows。
> **行数是信号，不是命令**——超 300 行才触发"评估"，同模块内容不硬拆。

### 4.5 AGENTS.md 的正确剂量

> Agent.md 的作用是"**导航和约束**"，不是"知识仓库"。
> 一份几百行的 AGENTS.md 会导致：上下文被污染、成本效率变差、**agent 弱智化**（规则冲突→变纯工具人）。

正解：AGENTS.md 管方向，其他文档管深度——只回答两个问题：
1. 你需要知道什么，才能安全开始工作？
2. 你遇到问题时，该去哪里找更详细的资料？

### 4.6 两个容易被忽略的实操坑

- **中文 skill 理解不如英文**：作者实测"对英文 skill 的理解程度要比中文高很多"；`1920math` 反馈"我写的是不准修改原文语句，它不改你的语句，它删！" → 建议**关键 skill 用英文写**。
- **必须写"什么时候不该用这个 skill"**：否则 skill 会**过度触发**，把简单问题复杂化。

- **数字员工范式**：从"人操作机器"到"**人训练数字员工**"——这是给管理层的叙事。

## 七、避坑清单与红线（培训必讲、客户最买账的一章）

| # | 坑 | 症状 | 对策 | 出处 |
|---|---|---|---|---|
| 1 | **AI 全权接管** | 线上出问题不知道怎么修，事故级损失 | 明确"AI 辅助"边界；代码/配置变更必须人复核 | `2968548`：某游戏公司"排期按 AI 开发速度评估"，社区强烈警告"全权给 AI 维护，to C 项目出一次事故就够呛" |
| 2 | **写回产线配置** | AI 直接改 Recipe / 产线参数 | **AI 只出建议，不写回本体**（安全边界） | 神州数码 DOE 案例 |
| 3 | **内网无法用外网工具** | Claude/Codex 在内网打不开 | 私有化轻量模型（Qwen 等）+ RAG | `2962465`、Saltware 混合引擎 |
| 4 | **成本失控** | 订阅费/中转费飙升、账号被封 | 先算用量再选渠道；号池需控并发 | `2999312`：号池"人多线程多打满烧得快也会封" |
| 5 | **数据外泄** | 商业机密进第三方中转 | 内网部署 or 可信私有渠道 | `2999312`："中转站数据可能被留存拿去卖" |
| 6 | **skill 写太长** | AI "读不到"，效果诡异 | 按需拆分；description 写准 | `1923706`："2000 字的 md，AI 根本读不到" |
| 7 | **AGENTS.md 写太厚** | agent 变"弱智"，规则互相冲突 | 只写导航和约束，十几行够用 | `1923706` |
| 8 | **中文 skill 失效** | "不准修改原文"→它给你删了 | 关键 skill 用英文写 | `1923706`、`1920math` |
| 9 | **Skill 安全隐患** | 第三方 skill 权限过大、数据外泄 | 权限最小化 + 静态检查 | `1374400` |
| 10 | **培训只讲不练** | "培训没用，得自己折腾" | 改工作坊，当天出活 | `1888765` 反方意见 |

> **安全章节的硬内容（`1374400`，企业客户最买账的一节）**
> 核心论点：**能力越强，风险越大——安装一个第三方 skill，等于把你的 User 权限完整交给这段代码。**
> - **权限模型是"裸奔"的**：skill/MCP 默认拥有完整文件系统读写（连 `~/.ssh/`、`~/.aws/`、`.env` 都能读）、任意网络请求、Shell 命令执行。
> - **两类典型攻击面**：
>   ① **隐蔽数据外泄**——伪装成"代码格式化"，实读环境变量里的 API Key，经 HTTP 或 DNS 隧道外传（可绕过简单防火墙）；
>   ② **供应链投毒**——skill 代码看着干净，但在安装依赖时作恶。
> → 给基本半导体的直接结论：**内网环境下"随便装 skill"是不可接受的**，必须建立"skill 准入 + 权限最小化 + 静态扫描"的内部机制。

## 八、交付建议

1. **形式**：工作坊（2 天），不是讲座。**当天必须让每个学员产出一个能用的 skill**——这是回应"培训没用"的唯一办法。
2. **首个样板**：优选**场景 1（测试报告自动化）**——痛感最强、见效最快、不碰产线边界，最容易建立信任。
3. **参考读物包**：把第三章 A/B 档的帖子整理成内部阅读清单（注意：这些是公开社区帖，可让学员自行查阅）。
4. **内部规范**：培训结束前，共同起草**一份十几行的 AGENTS.md**（导航+约束），作为团队 AI 使用的起点。
5. **后续陪跑**：参考同行做法，"**远程指导 + 积极回复**"，比一次性培训更有效。
6. **合规前置**：若客户内网，提前确认可用模型（Qwen 私有化）、数据边界、审批流程——**这一项决定培训能否落地**。
