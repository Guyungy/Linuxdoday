## 二、三个非显而易见的坑

### 坑 1：`--all` 是"捆绑开关"，会顺手关掉"跳过已抓"

`fetch_replies.py` 第 231-233 行：

```python
# 默认跳过已抓过的（除非 --all）
if not args.all:
    todo = [r for r in todo if str(r.get("id")) not in replies]
```

`--all` 本意是"全部时间范围"，却**同时禁用了去重跳过**。于是跑 `--all` 会把已抓过的帖子重刷一遍
（`--sort replies` 时尤其浪费——正好从最贵的巨型帖开啃）。

**正解**：用 `--recent-days 3650` 同时拿到"全时段"且保留跳过。干跑对比：

| 参数 | 待抓 |
|---|---|
| `--all --min-replies 1 --sort replies` | 14070（含已抓 1611 的重刷） |
| `--recent-days 3650 --min-replies 1 --sort replies` | **12443**（正确，跳过已抓） |

### 坑 2：`--sort replies` 会撞上"僵尸帖坟场"

`--sort replies`（回复最多优先）从队首开啃，而**历史失败帖永远留在队首**：帖子一旦被删（404），
它就不进 `replies`，下次又排在最前面，再失败再排前……形成坟场。

实测：连续 8 条全是 404（2771805 / 2940846 / 1670317 / 2879530 / 2825954 / 2945224 / 2779991 / 2409246），
且每条都可能附带一次 429，7 分钟颗粒无收。

**正解**：改用 `--sort time`（新帖优先），直接绕开坟场。改后立刻 **20/20 成功、0 失败、0 限流**。

### 坑 3：`/t/*.json` 端点比 HTML 页面更易吃 429

- 25 次 `pg.goto`（HTML 页面）+ 4s 间隔 → **0 次 429**。
- `fetch()` 打 `/t/<slug>/<id>.json` + 8~14s 间隔 → 约 **1/3 命中 429**。

结论：`.json` 走的是更严的限流；`--pace` 别低于 12s，并保留退避。

## 三、关键结论：站点**没有**因匿名而受限

一度怀疑"福利羊毛/文档共建 等板块对匿名返回 404"，实测**证伪**：

| 帖子 | 结果 | 板块 |
|---|---|---|
| 1957183 | **200**（Cursor++ 轻指南） | 文档共建 |
| 2879530 / 2978995 / 2995778 / 1670317 / 2825954 | 404 | 混杂 |

全表抽样 n=25（按回复数均布）：**22 条 200（88%）**，3 条 404，且 404 散落在各板块。

→ **404 不是权限问题，是帖子真的被删了**。匿名抓取可用，只是拿不到"登录可见"的私有内容。

> 附带教训：**已抓过的帖子现在也可能 404**（如 2975785，福利羊毛）——说明它是在登录态下抓的、后来被删或被移入受限区。所以"已抓 1611"这批的真实存活率无法用当前匿名状态回验。
